# Report and Message i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A run with `idm.test.report.locale: es` produces a Spanish HTML report — labels, evidence panels, and every step, engine, validation and runner message — while the JSON results keep their English `message` and gain `messageKey` / `messageArgs`.

**Architecture:** A Spring-free `Message(key, args)` record and a `Messages` renderer over two UTF-8 `.properties` catalogs in `idm-test-engine`. Phase 1 (Tasks 1–3) adds the locale setting and translates the report chrome. Phase 2 (Tasks 4–7) lets `StepOutcome` carry a `Message`, records its key and arguments in the results, and converts every message family to keys while keeping each English text character for character.

**Tech Stack:** Java 25, JDK `ResourceBundle` / `MessageFormat`, Jackson 3, JUnit 6, AssertJ, Spring Boot 4.1.1 (runners only).

**Spec:** `docs/specs/2026-10-12-report-i18n-design.md` (ITF-46). Tickets: Tasks 1–3 → ITF-47, Task 4 → ITF-48, Task 5 → ITF-49, Task 6 → ITF-50, Task 7 → ITF-51. ITF-52 (Spanish review) is done by jangulo after Task 7, before merge.

## Global Constraints

- Languages: `en` (default) and `es`. Never the JVM default locale: bundles are loaded with `ResourceBundle.Control.getNoFallbackControl(FORMAT_PROPERTIES)`.
- Setting sources, first non-blank wins: Spring property `idm.test.report.locale`, then env `IDM_TEST_LOCALE`, then system property `idm.test.locale`. Unsupported value → `unsupported report locale '<value>'; supported: en, es`, and the run stops before any scenario executes.
- Catalogs: `idm-test-engine/src/main/resources/com/idm/test/engine/i18n/messages.properties` (English) and `messages_es.properties` (Spanish), UTF-8.
- Key families: `report.*`, `evidence.*`, `step.<type>.*`, `engine.*`, `validation.*`, `runner.*`. Every key appears in code as a string literal (no keys built by concatenation), so the catalog test can find it.
- Patterns use only plain `{n}` placeholders — no `{n,number}`, `{n,choice}` or other format types. Arguments are rendered with `String.valueOf` (a nested `Message` is rendered in the same locale), so numbers never gain locale grouping. Plurals use a `.one` / `.other` key pair chosen in code.
- English output is unchanged: every English `message`, `failureDetail`, failure summary and report label stays exactly as it is today, character for character. No existing assertion on message or report text changes. (Refinement of spec §5: the English date pattern stays `yyyy-MM-dd HH:mm:ss z` because it comes from the catalog per locale; Spanish uses `dd/MM/yyyy HH:mm:ss z`.)
- Not translated: step types, YAML keys, author-written text (scenario/step/cleanup names and descriptions), error text from external systems (passed as an argument), logs, JSON field names.
- JSON: `messageKey` / `messageArgs` (and `failureDetailKey` / `failureDetailArgs` on a scenario) are `@JsonInclude(NON_NULL)` and come last, so a result without a key serializes exactly as today.
- Secrets (ITF-23): no password, token, client secret or Authorization value in any message, argument, report or log.
- Spanish: neutral Latin American Spanish, "usted" or impersonal forms; DN, LDAP, SQL, JSON, URL, timeout, step types and YAML keys stay as they are.
- The engine stays Spring-free (`NoSpringDependencyTest`). No new dependencies.

```java
package com.idm.test.engine.spi;

import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

/**
 * A user-facing message by key, with its arguments, so it can be shown in any supported
 * language (see {@code com.idm.test.engine.i18n.Messages}). Arguments are kept as plain values —
 * String, Number, Boolean, null — or a nested Message; anything else is turned into text when the
 * message is created, so results stay serializable.
 */
public record Message(String key, List<Object> args) {

    public Message {
        List<Object> plain = new ArrayList<>(args == null ? List.of() : args);
        plain.replaceAll(Message::plain);
        args = Collections.unmodifiableList(plain);
    }

    public static Message of(String key, Object... args) {
        List<Object> list = new ArrayList<>();
        if (args != null) {
            Collections.addAll(list, args);
        }
        return new Message(key, list);
    }

    private static Object plain(Object value) {
        return value == null || value instanceof String || value instanceof Number
                || value instanceof Boolean || value instanceof Message ? value : String.valueOf(value);
    }
}
```

`Messages.java`:

```java
package com.idm.test.engine.i18n;

import com.idm.test.engine.spi.Message;

import java.text.MessageFormat;
import java.util.Locale;
import java.util.MissingResourceException;
import java.util.ResourceBundle;

/**
 * Renders a {@link Message} from the catalogs {@code messages.properties} (English) and
 * {@code messages_es.properties}. A key missing in Spanish falls back to English; the JVM's
 * default locale is never consulted. A key missing everywhere, or a malformed pattern, renders as
 * {@code !key! [args]} — this never throws, so a catalog mistake cannot hide a failure.
 */
public final class Messages {

    static final String BASE = "com/idm/test/engine/i18n/messages";
    private static final ResourceBundle.Control NO_FALLBACK =
            ResourceBundle.Control.getNoFallbackControl(ResourceBundle.Control.FORMAT_PROPERTIES);

    private Messages() {
    }

    public static String render(Message message, Locale locale) {
        return render(message, locale, BASE);
    }

    /** The English text — what results record as {@code message}. */
    public static String english(Message message) {
        return render(message, Locale.ENGLISH);
    }

    static String render(Message message, Locale locale, String baseName) {
        Object[] args = message.args().stream()
                .map(arg -> arg instanceof Message nested ? render(nested, locale, baseName) : String.valueOf(arg))
                .toArray();
        String pattern = pattern(message.key(), locale, baseName);
        if (pattern != null) {
            try {
                return new MessageFormat(pattern, locale).format(args);
            } catch (IllegalArgumentException malformed) {
                // falls through to the visible marker
            }
        }
        return "!" + message.key() + "! " + java.util.Arrays.toString(args);
    }

    private static String pattern(String key, Locale locale, String baseName) {
        try {
            ResourceBundle bundle = ResourceBundle.getBundle(baseName, locale, NO_FALLBACK);
            return bundle.containsKey(key) ? bundle.getString(key) : null;
        } catch (MissingResourceException e) {
            return null;
        }
    }
}
```

`ReportLocale.java`:

```java
package com.idm.test.engine.i18n;

import java.util.List;
import java.util.Locale;

/** Which language a run's report uses: English unless the setting says Spanish. */
public final class ReportLocale {

    public static final List<String> SUPPORTED = List.of("en", "es");

    private ReportLocale() {
    }

    /** The first non-blank of the three sources, resolved; English when all are blank. */
    public static Locale resolve(String property, String env, String systemProperty) {
        for (String value : new String[]{property, env, systemProperty}) {
            if (value != null && !value.isBlank()) {
                return resolve(value);
            }
        }
        return Locale.ENGLISH;
    }

    public static Locale resolve(String value) {
        if (value == null || value.isBlank()) {
            return Locale.ENGLISH;
        }
        String tag = value.strip();
        return switch (tag.toLowerCase(Locale.ROOT)) {
            case "en" -> Locale.ENGLISH;
            case "es" -> Locale.of("es");
            default -> throw new UnsupportedLocaleException(tag);
        };
    }

    public static final class UnsupportedLocaleException extends IllegalArgumentException {
        UnsupportedLocaleException(String value) {
            super("unsupported report locale '" + value + "'; supported: " + String.join(", ", SUPPORTED));
        }
    }
}
```

## The conversion method (Tasks 5–7)

Each of Tasks 5–7 converts one group of files with this method. It is the same for every file.

1. **List every user-facing string the file builds** — any text that ends up in a `StepOutcome`, an exception whose message reaches a result or report (`ExpressionException`, `ValidationException`, `IllegalArgumentException` caught and reported by a step), or a runner failure. Logs (`LOG.*`) are not converted.
2. **One key per distinct sentence shape,** named `step.<type>.<what>` (e.g. `step.ldap.verify.mismatch`) or the group's family. Shared shapes used by several steps of one family may share a key (`step.ldap.notFound`).
3. **The English pattern reproduces today's text exactly.** Each concatenated value becomes `{n}` in order; a literal `'` becomes `''`; a literal `{` or `}` is quoted (`'{'`). Values are passed as arguments unchanged — including external error text (`e.getMessage()`) and values that are already masked today (never unmask anything to build an argument).
4. **Replace the string with `Message.of("<key>", args…)`** and the factory with its `Message` form: `StepOutcome.failure(Message)`, `success(Message[, value])`, `finalFailure(Message)`. For an exception, give the exception a `Message`: add a constructor `XxxException(Message detail[, Throwable cause])` that calls `super(Messages.english(detail), cause)` and stores `detail`, with a `Message detail()` accessor; the code that turns the exception into an outcome uses `detail()` when it is not null.
5. **Plurals:** `.one` / `.other` keys chosen in code (`n == 1 ? "…one" : "…other"`). Text that today says `row(s)` keeps `row(s)` in English: one key, and the Spanish pattern says `fila(s)`.
6. **Spanish entry** for every new key (Global Constraints style).
7. **Tests:** no existing assertion on English text changes. Add one test per file that its most common failure renders in Spanish (`Messages.render(outcome.detail(), Locale.of("es"))` contains a distinctive Spanish word), in that file's existing test class.
8. **Before committing:** the catalog test, the module's tests, the full-suite check and the baseline comparison (Task 4 Step 7) all pass.

```java
package com.idm.test.engine.i18n;

import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;
import java.util.regex.Pattern;
import java.util.stream.Stream;

import static org.assertj.core.api.Assertions.assertThat;

/**
 * Engine messages go through keys (ITF-46), so every one can be shown in Spanish. The String
 * forms of StepOutcome stay for third-party steps; this test keeps the engine itself off them.
 */
@DisplayName("Engine messages use keys")
class NoPlainMessagesTest {

    private static final Pattern PLAIN = Pattern.compile(
            "StepOutcome\\.(success|failure|finalFailure)\\(\\s*\"");

    @Test
    @DisplayName("No engine source builds a StepOutcome from a string literal")
    void testNoPlainOutcomes() throws IOException {
        try (Stream<Path> files = Files.walk(Path.of("src/main/java"))) {
            List<String> offenders = files.filter(p -> p.toString().endsWith(".java"))
                    .filter(p -> {
                        try {
                            return PLAIN.matcher(Files.readString(p)).find();
                        } catch (IOException e) {
                            throw new java.io.UncheckedIOException(e);
                        }
                    })
                    .map(Path::toString).toList();
            assertThat(offenders).as("engine sources building StepOutcome from text; use Message").isEmpty();
        }
    }
}
```

This replaces the spec's "deprecate the String forms" (deprecation would put warnings into every test that builds a plain outcome, against ITF-45's no-warnings rule); it enforces the same thing. Strings built by concatenation and passed to the `String` factories are caught by the review and by `CatalogTest`'s coverage, not by this test.
